# Market opportunity workflow

Use after reading the main page. Goal: a defensible size estimate and a competitive picture, with every number tagged `given`, `sourced` or `assumption`. Never invent market data; if a figure is missing, list it as a gap.

## Step 1. Frame the question

- Product in one sentence; the buyer (who pays) and the user (who uses), if different.
- Business model type: subscription software, marketplace, consumer, services, hardware.
- Geography, currency, time horizon (default: year 3 and year 5).
- The decision this estimate feeds: build or not, raise or not, enter a region or not.

## Step 2. Segment the buyers

Split the potential buyers into 3 to 6 concrete segments. For each: how to recognise them, rough count (tagged), pain level (low, medium, high), and how you would reach them. Rank by pain and reachability. Start with the top one or two segments only.

## Step 3. Bottom-up estimate

For each priority segment:

| Line | Value | Tag | Source or reasoning |
|---|---|---|---|
| Reachable buyers | | | |
| Share that fits the product today | | | |
| Purchases per year | | | |
| Price per purchase | | | |
| Segment SAM | | | |

Then SOM: customers the team can close per month x months in the horizon, adjusted for churn, times price. State the sales capacity assumption (people, channels, conversion) next to it.

## Step 4. Top-down cross-check

1. Ask the user for a published figure for the wider industry (or search with the platform's tool and cite it).
2. Narrow in stages: geography, segment, use case, willingness to pay. One percentage per stage, each with a reason.
3. Compare with the bottom-up SAM. Record the ratio.
4. If the ratio is above about 2x either way (reference point), investigate before reporting: wrong segment counts, price too high or low, double counting, or an outdated figure.

## Step 5. Scenarios

Low, base and high cases that differ in a few named inputs (buyer count, price, adoption speed), not in everything at once. Show the one input that moves the result most.

## Step 6. Market health (qualitative unless data supplied)

- Growth direction and what drives it (regulation, technology shift, behaviour change).
- Timing: why now and not three years ago.
- Headwinds: budget cycles, long sales cycles, incumbents' lock-in.

## Step 7. Competitive landscape

1. Three rings: direct, indirect, status quo. Aim for 5 to 10 names in total; fewer is fine if the market is small.
2. For each: who they serve, how they charge, what they do well, where buyers complain (only from sources the user provides or the platform's read tool; otherwise mark `assumption`).
3. Comparison table on 4 to 6 buyer criteria.
4. Five Forces summary, one line per force.
5. Positioning map on two axes that buyers actually care about; place each player and name the empty area. Check that the empty area has buyers.
6. Durability: what keeps this position for 12 to 24 months.

## Step 8. Assemble the output

```
# Market opportunity: [venture]
Summary (answer, confidence, biggest unknown)
Method and assumptions table
TAM / SAM / SOM with low, base, high
Top-down vs bottom-up comparison and the gap explained
Competitive table, Five Forces, positioning verdict
Gaps and how to close them
Next step this week
```

## Red flags to call out

- SOM expressed only as a percent of TAM.
- Segment counts taken from a whole population with no filter.
- Price assumed equal to a rival's with no evidence of willingness to pay.
- A market described as having "no competitors" (the status quo always exists).
- A single source behind every figure.

## Cheap ways to tighten an estimate

- Ten short buyer interviews on price and current spend.
- A count from a public directory or a customer list the user already owns.
- A landing page or pre-order test, run only with the user's approval.
