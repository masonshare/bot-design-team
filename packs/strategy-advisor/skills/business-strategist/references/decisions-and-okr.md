# Decisions, OKRs and templates (compact)

## 1. Decision-quality tools

Use them in this order for a real choice. Skip layers for small decisions.

1. **Opportunity cost.** For each option, name the best alternative use of the same money, people and time. "Compared with what?" is the question.
2. **Second-order thinking.** For each option ask "and then what?" twice: first effect, then the reaction of customers, competitors, staff and the market to that effect.
3. **Inversion.** Ask how to guarantee failure, then check whether the plan contains any of those moves. Also ask what a smart competitor would do to beat this plan.
4. **Expected value.** For the top options estimate two or three outcomes with a probability and a value. Probabilities are assumptions: label them, and show how the pick changes if a probability is off by a third.
5. **Regret check for irreversible moves.** Ask which choice the user would regret least in ten years or after the worst case happens. Reversible choices should be made fast with less information; irreversible ones deserve more evidence.

Also: separate facts, estimates and opinions in the evidence column; look for the evidence that would disprove the preferred option; set the decision date and the information that would change it.

## 2. Pre-mortem

Assume the plan failed 12 months from now. Write three most likely causes, ranked by likelihood times damage. For each: early warning sign, owner who watches it, and a mitigation to prepare now. Common causes: the assumption nobody tested, a dependency outside the team's control, cash running out before results, key person leaving, the market reacting differently.

## 3. OKR rules

- An objective is a short, qualitative, motivating statement of what to achieve this quarter. Three at most.
- Each objective has three or four key results: measurable outcomes with a baseline, a target and a date. A key result is a result, not a task ("increase 90-day retention from 62% to 70%", not "launch onboarding emails").
- Mix leading (activation, pipeline) and lagging (revenue, retention) indicators.
- Aim so that about 70% achievement is a good quarter for stretch goals; committed goals should be hit fully. Label which are which.
- Each key result has one owner and a weekly check-in value.
- Tie every objective to the strategy choice: if an objective does not trace to the chosen position, drop it.
- Decompose a yearly goal backwards: target, required volume at each funnel stage, required capacity or spend, quarterly milestones.

## 4. Template: options table

| Option | Upside | Downside | What must be true | Evidence or assumption | Verdict |
|---|---|---|---|---|---|
| A | | | | given / pasted / assumption | |
| B | | | | | |
| C (smallest version or do nothing) | | | | | |

Below the table: pick, the two reasons that decided it, and the signal that would reverse it.

## 5. Template: risk register

| Risk | Likelihood (L/M/H) | Impact (L/M/H) | Early warning sign | Mitigation | Owner |
|---|---|---|---|---|---|

Rules: at least three rows; likelihood and impact are judgments, so say they are; sort by likelihood times impact; each mitigation is an action, not a hope.

## 6. Template: priority list

| Priority | Start / Stop / Do not do | Owner | Metric it moves | Review date |
|---|---|---|---|---|

Keep at most five starts. A priority list with no "stop" or "do not do" rows is a wish list.

## 7. Template: current-state table (Auditor)

| Metric | Value | Reference point | Gap | Source or assumption |
|---|---|---|---|---|

Reference points come from `economics-and-growth.md` or from the user's own history; always say which.

## 8. Handoff block (to any downstream agent or teammate)

- Stage and mode used
- Decision taken or key finding (one or two sentences)
- Numbers it rests on, each tagged given or assumption
- Deliverable needed, audience, constraints
- Open questions and the data still missing
