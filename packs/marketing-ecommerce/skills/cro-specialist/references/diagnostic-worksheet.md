## C. Page protocol

1. Five-second look: what is this, for whom, what do I do.
2. LIFT six factors, each with pass / weak / fail and evidence.
3. Message match against each main traffic source.
4. Scroll and click evidence: where attention goes, where it stops.
5. Mobile pass: first screen, tap targets, form ease.
6. Root cause: motivation or friction, then the B=MAP gap.

## D. Form protocol

1. **Length:** list each field, mark essential or deferrable. Ask "does removing it block the sale or follow-up?"
2. **Difficulty per field:** time, thinking effort, anything unexpected or hard to format.
3. **Perceived friction:** grouping, labels, whitespace, progress indicator in multi-step forms.
4. **Anxiety:** sensitive fields (phone, card, company data), is reassurance next to each?
5. **Button:** does it say what happens next, is it the clear final prompt?
6. **Field analytics if available:** which field has the highest abandonment, longest time, most corrections. Start from the data, use steps 1 to 5 to explain it.
Invented example: 62 percent of starters leave at the phone field; reason hypothesis: no stated use for the number. Fix direction: make it optional or explain the use.

## E. Flow protocol

1. Map the real path (what users actually do, not the intended diagram).
2. Conversion from each step to the next, by source, device and new versus returning.
3. Rank drop-offs, work on the largest first, do not fix everything at once.
4. At each leaking step run the trinity: relevant now, value clear, next action obvious.
5. List each small yes the visitor must give and the reason offered for it.
6. Prompt chain: does every step end with a clear pointer to the next?
7. Consistency: message, design and promise hold from step to step, with no surprise costs late in the flow.
