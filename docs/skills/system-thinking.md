# system-thinking

## What it does

Analyses a problem as a system in four steps (big picture, root cause, connections and feedback loops, workflow solution) and returns a report with four fixed sections. It lists broadly first and prunes later, asks "why" at least three layers deep, and hunts for feedback loops and delays. Gaps are written as assumptions, never invented.

Many problems repeat because people fix the symptom. Stopping at the first "why" almost always lands on a symptom, so the minimum is three layers. The four report sections keep fixed names so results can be compared. Every number in this skill is a labelled reference point, not a fact about your market; the skill asks for your own figures.

Source: [`packs/strategy-advisor/skills/system-thinking/SKILL.md`](../../packs/strategy-advisor/skills/system-thinking/SKILL.md)

## When to reach for it

A problem keeps coming back, fixes cause side effects, or the user asks for a systems-thinking analysis, root cause, or a process debug. If a diagram would help, pair it with a diagramming skill if you have one.

## Common questions

**What does the report look like?** Four sections: big picture, root cause, connections, solution as a workflow.

**What if it lacks information?** It marks the gap as an assumption and asks, rather than inventing.

**Is it only for business problems?** No. Any recurring problem with several moving parts fits.

## It's working if

- The report has the four fixed sections.
- The root-cause section goes at least three "why" layers deep.
- Feedback loops and delays are named, and unknowns are flagged as assumptions.
